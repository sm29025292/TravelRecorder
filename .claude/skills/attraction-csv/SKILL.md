# 景點整理 → TravelRecorder 景點 CSV

把使用者給的 Google 地圖網址整理成 **T49 標準格式** CSV，讓使用者在 App「景點庫 → 匯入 CSV」直接匯入
（匯入前 App 會先顯示預覽；已存在的景點只補空白欄位、不覆蓋）。

回覆一律使用**繁體中文、台灣常用說法**。

## 核心原則：先拿到「含座標的長網址」

Google 地圖長網址本身就帶有最可靠的資訊（設計依據：2026-10-06「景點庫：貼 Google 地圖連結自動預填」實測）：

| 網址型態 | 例 | 能拿到 |
|---|---|---|
| 分享短網址 | `maps.app.goo.gl/…` | 什麼都沒有 → **先展開** |
| 手機 App 剛轉址的長網址（手機分享的短網址常展開成這種） | `…/place/新宿諏訪神社+1+Chome-12-6+Takadanobaba,…/data=…?entry=gps`、`…/place/箱島神社86+Nijohamakubo,+Itoshima,…819-1614日本/…` | 名稱＋Google 英文地址（黏在一起，可能沒有空格），**沒有座標** |
| 地圖載入完／短網址展開後的長網址 | `…/place/新宿諏訪神社/@35.70,139.70,17z/data=…!3d35.7090446!4d139.7076507…` | 乾淨名稱＋**地點精確座標**（`!3d…!4d…`）＋ place id |

- 名稱、座標、Google 英文地址**一律取自長網址**，不要靠搜尋「猜」是哪個地點。
- **座標（或 Google 英文地址）是判斷真偽的基準**：國家／都市／區域／地址都必須和它一致。
- **不使用 Nominatim 或任何反向地理編碼 API**；也不要抓 Google 未公開的搜尋／地圖介面。
  國家、都市、區域由座標判斷（你對世界主要城市的經緯度範圍有足夠知識），地址由公開網頁查證。

## 輸出格式（不可更動）

```
國家,地點,區域,類型,景點,地址,網址,備註,優先度
```

| 欄位 | 規則 |
|------|------|
| 國家 | 台灣常用中文國名：日本、韓國、台灣、泰國、越南、美國… |
| 地點（都市） | **一級行政區**，去掉「都／府／縣」字尾、用台灣常用中文：日本＝都道府縣（東京、大阪、京都、福岡、北海道、沖繩）；韓國＝特別市／廣域市／道（首爾、釜山、濟州、京畿）；台灣＝直轄市／縣（台北、新北、花蓮）；泰國＝府（曼谷、清邁）。例：太宰府市、糸島市的景點都市都填「福岡」 |
| 區域 | **有商圈寫商圈，沒有就寫二級行政區**。商圈＝知名商圈／觀光地區／代表車站周邊（心齋橋、難波、梅田、天神、博多、銀座、澀谷、新宿、淺草、明洞）；沒有商圈時填二級行政區：市町村／東京特別區（日本的「市」去字尾：太宰府、糸島；町、村、區保留：世田谷區）；**政令指定都市**（大阪市、福岡市、京都市、橫濱市、名古屋市、札幌市等有行政區的大城市）改填市內的區（西區、博多區、中京區）。住宅區、辦公區的地名或車站名（例：阿波座）不算商圈。商圈與行政區都以座標或 Google 地址所在位置為準，無把握就留空，**不要硬填** |
| 類型 | 只能是 `景點`／`美食`／`住宿`／`交通` 之一（見下方判斷） |
| 景點 | **以長網址解析出的名稱為準**；有台灣常用中文名可改用（大阪城、清水寺），店家／飯店保留官方原名；名稱含罕見字（`rareChars: true`）時見步驟 4 |
| 地址 | 當地官方地址（當地語言原文）；查證不到就留空並標待確認 |
| 網址 | 名稱固定為「Google Map」、連結為使用者給的**原始**網址（短網址就填短網址，不填展開後的長網址）；腳本會自動組成 `[Google Map](網址)` |
| 備註 | **只放使用者在網址後面附的文字**（見下方） |
| 優先度 | 0–3；使用者沒說就留 0（空白） |

## 備註

**只放使用者在網址後面附的文字**，原文照錄（例 `https://maps.app.goo.gl/xxxx 御守` → 備註「御守」）；沒有附文字就留空。
**不要**自行加入營業時間、特色、交通方式、注意事項或「待確認」——查不到、有疑慮的欄位一律在回報中告訴使用者，不寫進備註。

**類型判斷**：餐廳、咖啡廳、小吃、甜點店、居酒屋、市場美食 → `美食`；飯店、旅館、民宿 → `住宿`；
機場、車站、港口、巴士站 → `交通`；其餘（寺廟、神社、公園、博物館、購物商場、展望台…） → `景點`。

## 步驟

以下指令的路徑皆相對於 repo 根目錄。

1. **收集輸入**：一行一個網址；網址後面若有文字（以空白隔開），那段文字原文放進該筆的**備註**。
   使用者若指定優先度、都市／區域寫法，記下來優先採用。
   只給名稱沒給網址的，請使用者補上 Google 地圖連結（沒有座標無法確認是哪一個地點）。

2. **展開成長網址**：
   ```bash
   bash .claude/skills/attraction-csv/scripts/expand-url.sh "<url1>" "<url2>"
   ```
   只追 HTTP 轉址、不讀頁面。結果為 `ERROR`（網路被擋、Google 拒絕）時，請使用者：
   「在**瀏覽器**打開連結（手機請長按選『在瀏覽器開啟』），**等地圖顯示出來**，再複製網址列的完整網址貼回來」。

3. **離線解析長網址**：
   ```bash
   node .claude/skills/attraction-csv/scripts/parse-maps-url.mjs "<長網址1>" "<長網址2>"
   ```
   依 `kind` 處理：
   - `long-coords`：取 `name`、`lat`／`lng`（`coordSource: "place"` 最準；`"viewport"` 只是地圖中心，需在回報中提醒）。
   - `long-no-coords`（手機 App 分享的短網址常展開成這種）：沒有座標，但通常有 `addressHint`
     （Google 自己的英文地址，例 `86 Nijohamakubo, Itoshima, Fukuoka 819-1614`）與 `countryHint`。
     **`addressHint` 等同座標的比對基準**：國家／都市由它判斷，查到的當地語言地址必須與它是同一個地址
     （番地、郵遞區號一致）。連 `addressHint` 都沒有時，才請使用者照步驟 2 的說明重貼「地圖載入完」的網址。
     `nameMayIncludeAddress: true` 表示名稱裡可能夾著地址、沒切乾淨，需人工判斷名稱。
   - `invalid`：不是 Google 地圖網址，請使用者確認。

4. **由座標定位置、再查證**：
   - 先用座標判斷國家、都市、所在行政區／鄰近車站（例：34.6789, 135.4910 → 日本・大阪府大阪市西区，附近無商圈 → 都市「大阪」、區域「西區」；`883 Uchiyama, Dazaifu, Fukuoka` → 都市「福岡」、無商圈 → 區域「太宰府」）。
   - 用「名稱＋都市／行政區」做 WebSearch，從官方網站、觀光局、Tabelog、旅遊媒體取得地址與類型。
   - 沒有座標、只有 `addressHint` 時：直接以它判斷國家／都市／區域，並找出對應的當地語言地址。
   - **一致性檢查（必做）**：查到的地址必須落在座標所在的同一行政區（區／町），或與 `addressHint` 為同一地址。
     不一致 → **不得改成另一個名稱相近的地點**，在回報中說明落差並請使用者確認。
   - **名稱含罕見字（`rareChars: true`）**：Google 用了 Unicode 擴充區的字（例「𢲡抬𢲡撸神社」＝サムハラ神社），
     不要找字形相似的名稱代替；改以「座標所在行政區＋類別」搜尋（例「大阪市西区 立売堀 神社」）找出實際名稱，
     找不到就保留原名稱並請使用者確認。
   - 查不到或來源互相矛盾的欄位：留空，在回報中標出（不寫進備註）。**絕對不要編造地址**。

5. **寫成 JSON**：存到 `exports/attractions-<YYYYMMDD>.json`（`exports/` 已在 `.gitignore`），每筆：
   ```json
   {"country":"日本","city":"大阪","district":"西區","type":"景點","name":"サムハラ神社",
    "address":"大阪府大阪市西区立売堀2丁目5-26","url":"https://maps.app.goo.gl/xxxx","notes":"","priority":0}
   ```

6. **輸出 CSV**（腳本負責跳脫逗號／引號、加 BOM、驗證欄位）：
   ```bash
   node .claude/skills/attraction-csv/scripts/to-csv.mjs exports/attractions-<YYYYMMDD>.json exports/attractions-<YYYYMMDD>.csv
   ```
   驗證失敗會列出問題，修正 JSON 後重跑。**不要手寫 CSV**。

7. **回報**：用表格列出每筆的 國家／都市／區域／類型／名稱／地址，附長網址解析出的座標，
   列出所有留空或有疑慮的欄位，附查證來源連結與 CSV 路徑，提醒使用者到 App「景點庫 → 匯入 CSV」選這個檔，
   在預覽確認後按「確定匯入」。

## 注意

- 使用者的景點清單是個人資料：**不要把 `exports/` 內的檔案 commit 進 repo**（本 repo 是 public）。
- 同一地點（同 place id 或同座標）重複出現只輸出一筆。
- 都市與區域名稱要前後一致（同一批不要一下「難波」一下「なんば」），App 以「國家＋都市＋區域＋名稱」判斷是否為同一景點；
  使用者若提過景點庫裡既有的寫法，照那個寫法。
