# 景點整理 → TravelRecorder 景點 CSV

把使用者給的 Google 地圖網址（`maps.app.goo.gl` 短網址、`google.com/maps/place/...` 完整網址）
或純文字地點名稱，整理成 **T49 標準格式** CSV，讓使用者在 App「景點庫 → 匯入 CSV」直接匯入
（匯入前 App 會先顯示預覽；已存在的景點只補空白欄位、不覆蓋）。

回覆一律使用**繁體中文、台灣常用說法**。

## 輸出格式（不可更動）

```
國家,地點,區域,類型,景點,地址,網址,備註,優先度
```

| 欄位 | 規則 |
|------|------|
| 國家 | 台灣常用中文國名：日本、韓國、台灣、泰國、越南、美國… |
| 地點（都市） | 台灣常用中文城市名：大阪、京都、東京、首爾、曼谷… 用「市／主要觀光城市」層級，不要寫都道府縣（例：寫「大阪」而非「大阪府」） |
| 區域 | 城市內的知名區域／商圈：心齋橋、難波、梅田、淺草、新宿、明洞… 無明確區域就留空，**不要硬填** |
| 類型 | 只能是 `景點`／`美食`／`住宿`／`交通` 之一（見下方判斷） |
| 景點 | 景點名稱：有台灣常用中文名就用中文（大阪城、清水寺）；店家／飯店用官方名稱（可保留日文、英文原名，例「蟹道樂 道頓堀本店」） |
| 地址 | Google 地圖上顯示的當地官方地址（當地語言原文即可） |
| 網址 | 使用者給的**原始**網址；腳本會自動包成 `[Google 地圖](網址)` |
| 備註 | 需要使用者確認的事項、營業時間、價位等簡短資訊；不確定的欄位寫「待確認：…」 |
| 優先度 | 0–3；使用者沒說就留 0（空白） |

**類型判斷**：餐廳、咖啡廳、小吃、甜點店、居酒屋、市場美食 → `美食`；飯店、旅館、民宿 → `住宿`；
機場、車站、港口、巴士站 → `交通`；其餘（寺廟、公園、博物館、購物商場、展望台…） → `景點`。

## 步驟

1. **收集輸入**：列出使用者給的每個網址或名稱。使用者若有指定優先度、備註、想用的都市／區域名稱，記下來優先採用。

2. **解析完整網址（離線）**：對 `google.com/maps/...` 完整網址執行
   ```bash
   node .claude/skills/attraction-csv/scripts/parse-maps-url.mjs "<url1>" "<url2>"
   ```
   取得地點名稱、座標、place id。回傳 `short: true` 的是短網址，進第 3 步。

3. **展開短網址**：依序嘗試，成功一個即可：
   - `curl -sSIL -o /dev/null -w '%{url_effective}' "<短網址>"` 取得最終網址，再跑第 2 步。
   - 用 WebFetch 讀該網址。
   - 都失敗（網路被擋、Google 拒絕）時，**不要猜**：請使用者在瀏覽器打開該連結，把網址列的完整網址或店名貼回來。

4. **補齊國家／都市／區域／地址／類型**：以地點名稱（＋座標）用 WebSearch／WebFetch 查詢官方網站、Google 地圖、
   Tabelog、旅遊網站等。座標可以輔助確認城市與區域。
   - 查到的資訊互相矛盾、或只查到部分欄位：留空該欄，在備註寫「待確認：地址」之類。
   - **絕對不要編造地址**。

5. **寫成 JSON**：存到 `exports/attractions-<YYYYMMDD>.json`（`exports/` 已在 `.gitignore`），每筆：
   ```json
   {"country":"日本","city":"大阪","district":"心齋橋","type":"美食","name":"蟹道樂 道頓堀本店",
    "address":"大阪府大阪市中央区道頓堀1-6-18","url":"https://maps.app.goo.gl/xxxx","notes":"","priority":0}
   ```

6. **輸出 CSV**（腳本負責跳脫逗號／引號、加 BOM、驗證欄位）：
   ```bash
   node .claude/skills/attraction-csv/scripts/to-csv.mjs exports/attractions-<YYYYMMDD>.json exports/attractions-<YYYYMMDD>.csv
   ```
   驗證失敗會列出問題，修正 JSON 後重跑。**不要手寫 CSV**。

7. **回報**：用表格列出每筆的 國家／都市／區域／類型／名稱，標出所有「待確認」的欄位，
   附上 CSV 檔案路徑，提醒使用者到 App「景點庫 → 匯入 CSV」選這個檔，在預覽確認後按「確定匯入」。

## 注意

- 使用者的景點清單是個人資料：**不要把 `exports/` 內的檔案 commit 進 repo**（本 repo 是 public）。
- 同一地點重複出現只輸出一筆。
- 都市與區域名稱要前後一致（同一批不要一下「難波」一下「なんば」），App 以「國家＋都市＋區域＋名稱」判斷是否為同一景點；
  使用者若提過景點庫裡既有的寫法，照那個寫法。
